# WBOT 20DoF 走路 + 踢球 + 翻身 + 起立

同一 MuJoCo 场景、同一机器人，通过 Viser 切换四套策略。

```bash
cd /home/songhat/code_workspace/unitree_rl_mjlab
./scripts/play_walk_kick.sh
```

浏览器打开 `http://localhost:8095`，远程可用服务器地址，或 SSH 转发 8095 端口。
默认监听 `0.0.0.0:8095`；可传 `--viser-host 127.0.0.1 --viser-port 8096`。
Python 环境可通过 `WALK_KICK_PYTHON` 覆盖。

Walk / Kick 默认从以下目录选择编号最大的 `model_<数字>.pt`，忽略导出文件：

- Walk：`DroidUpE1_mjlab/logs/rsl_rl/wbot_20dof_walk_run_amp/2026-09-24_08-55-34`，当前为 `model_48900.pt`。
- Kick：`unitree_rl_mjlab/logs/rsl_rl/wbot_20dof_kick/2026-09-24_16-56-09_ball_perenv_pelvis_exclude`，当前为 `model_30000.pt`。
- Get Up：固定加载 `unitree_rl_mjlab/logs/rsl_rl/wbot_20dof_getup_tracking/2026-09-28_15-38-09_wbot_20dof_roban_no_state_estimation/model_30000.pt`；可用 `--getup-checkpoint` 覆盖。

可以用 `--walk-checkpoint <文件或目录> --kick-checkpoint <文件或目录>` 指定。

## 操作

- 启动进入 Walk，球放在机器人附近并持续参与物理仿真；零速度也执行走路策略。
- `vx / vy / wz` 分别控制前后、横向和转向速度。
- `Kick`：保留机器人和球的当前位置、速度，参考动作从第 0 帧开始。
- 踢球片段播放一次后保持最后一帧；按 `Walk` 切回走路，速度指令归零。
- `Reset Environment`：恢复默认站姿、把球放回机器人附近、清空动作并重建走路历史。
- `Reset Ball`：需要时手动把球放回机器人当前朝向的踢球位置。
- 可选 `--stand-hold` 在零指令时用 PD 保持默认姿态。

## 观测和动作

| 项目 | Walk AMP | Kick |
| --- | --- | --- |
| 输入 | 345 = 5 × 69 | 109，单帧 |
| 顺序 | 每帧：torso 角速度 × 0.2、重力方向、速度指令、关节相对默认位置、关节速度 × 0.05、上一动作 | 参考关节位置/速度 40、参考 anchor 相对旋转矩阵前两列 6、根角速度 3、关节位置 20、关节速度 20、上一动作 20 |
| 历史 | 按帧排列，旧→新；切回 Walk 时用当前帧填充 | 无历史 |
| 归一化 | 无 | checkpoint 自带的 mean/std，通过原 runner 加载 |
| 动作 | 默认关节角 + 0.25 × action | 默认关节角 + 训练配置的逐关节 scale × action |

20 个关节顺序在启动时检查；切回 Walk 时上一动作换算为 Walk 的缩放单位。
踢球参考朝向按进入 Kick 时机器人的 yaw 对齐，保持参考动作本身的 roll/pitch。
两策略控制周期均为 0.02 秒（物理步长 0.005 秒，decimation=4）。

场景沿用 Kick 的球，机器人使用 Get Up 的同质量、同电机版本，髋关节俯仰限位放宽至 ±3.14 rad，保留 pelvis 碰撞排除；演示关闭推力、COM/编码器/摩擦等随机化及奖励计算，默认关闭终止条件。四套策略未经过联合训练，任意高速切换的稳定性仍需实测；摔倒时使用 Reset。

## 网页摇杆与实体手柄

展开 **手柄 / 网页摇杆**，选择输入方式并点击 **启用控制**：

- 网页摇杆：用鼠标拖动或触屏操作两个圆盘，松开即归零。服务器 IP 的 HTTP 页面也能用。
- USB / 蓝牙手柄：手柄连接到打开网页的电脑，选择此模式后按一下手柄按键。支持浏览器标准映射（Xbox / PlayStation）。
- 左摇杆：上下控制前后速度，左右控制横移；右摇杆左右控制转向。
- A / ×：Walk；B / ○：Kick；X / □：停止并回到 Walk；Y / △：Reset Ball。
- RB / R1：Get Up 原地起立。
- LB / L1：Roll 翻身，俯卧后自动起立，再切回 Walk。
- 网页上的 Walk / Kick / Get Up / 放球 / 停止按钮与手柄映射相同。

前进最大 1.2 m/s、后退 0.8 m/s、横移 0.5 m/s、转向 1.5 rad/s；实体摇杆死区为 0.12。启用后摇杆接管速度，关闭后可用原滑条。切换策略保留球位置，只有“放球 / Y”会重新摆球。

浏览器的 [Gamepad API](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/getGamepads) 需要安全上下文；实体手柄请通过 `http://localhost:8095` 或 HTTPS 访问。远程可将服务器 8095 端口用 SSH 转发到本机 8095，再打开 localhost。无需在服务器连接手柄或安装手柄驱动。

断开手柄、关闭面板控制、网页失去焦点或切到后台时速度归零；控制连接中断时服务端最多 0.4 秒后归零。速度归零不会自动中断正在执行的 Kick，按 X / “停止”可切回 Walk。一个网页持有控制时，其他网页的摇杆输入不会覆盖它。

## 球的滚动阻力

当前演示对球启用 `condim=6`，摩擦参数为 `(0.7, 0.01, 0.015)`（滑动、扭转、滚动）。[MuJoCo 接触模型](https://mujoco.readthedocs.io/en/latest/computation/)中的滚动摩擦会消耗球滚动时的能量。启动参数 `--ball-rolling-friction 0.02` 可进一步增强阻力，默认 `0.015`；此配置只应用于合并演示。

实测初速 2 m/s 的纯滚动球，约 2.4 秒后降至 0.03 m/s 以下，移动约 2.46 米，6 秒时速度接近零。停止距离会随实际踢球速度变化。


## 第三个模型：起立

- **Get Up（原地起立）**：保持当前机器人和球的物理状态，从起立参考第 0 帧开始执行策略。它针对训练中的俯卧姿态，其他倒地姿态不保证成功。
- **Prone → Get Up（趴下并起立测试）**：显式把机器人放到训练参考的起始俯卧姿态，保留当前水平位置及朝向，不移动球，再运行起立模型。
- 参考片段共 851 帧、50 Hz。片段结束且根高度大于 0.45 m、姿态接近直立时，自动回到 Walk 并清零速度；否则停留在起立末帧并显示未直立状态。
- Get Up 也是 109 维单帧观测，字段布局与 Kick 相同，但采用**独立的参考动作时钟、朝向对齐、checkpoint mean/std 和动作缩放**。Walk 仍为 345 维历史观测。
- 三个模式都在同一个场景和机器人上执行，球和手柄保留；力矩条在 **Joints** 标签页。

完整 `--smoke-test` 包含起立→走路→踢球→走路、观测维度与公共字段一致性、独立时钟及归一化检查。

SSH 转发合并仿真的端口：

```bash
ssh -N -L 8095:127.0.0.1:8095 songhat@172.30.0.10
```

浏览器打开 `http://localhost:8095`。独立起立演示仍使用 8096。

本次完整验证已通过：俯卧起立后自动回到 Walk，接着 Kick 并切回 Walk 全程保持站立；最后一次踢球位移约 1.73 米。浏览器模拟 RB 起立键和单次触发检查也已通过。


## 第四个模型：翻身到俯卧

默认从 `logs/rsl_rl/wbot_20dof_roll_to_prone_tracking` 的最新训练子目录选取最高编号的 checkpoint。
本地清理后该目录可能为空，需重新训练或用 `--roll-checkpoint` / `CHECKPOINT_FILE` 指定其它机器上的权重。

- **Roll（翻身→起立） / LB / L1**：保留当前机器人和球状态，执行仰卧到俯卧的策略。
- **Supine → Roll（仰卧翻身测试）**：显式把机器人放到翻身参考的初始仰卧姿态，保留水平位置，不移动球，用于演示完整恢复链。
- 翻身参考 131 帧、50 Hz。片段结束后，躯干重力投影与目标俯卧方向误差小于 0.65 时，自动切到 Get Up；起立完成后自动回到 Walk。未达到俯卧则继续保持翻身末帧，并显示 `not prone`。
- Roll 使用独立的 109 维观测、参考时钟和 checkpoint 归一化统计。仰卧状态的朝向对齐使用相对旋转，避免绝对 yaw 在躺平时退化。
- 共享场景继续使用原先已验证的机器人碰撞配置和 `0.005 × 4` 物理步长；翻身原训练为 `0.004 × 5` 并带额外地面碰撞网格，两者策略周期均为 0.02 秒。已在共享配置下验证恢复链，但不代表任意倒地姿态都能恢复。
- `--smoke-test` 还会验证转向 1.1 rad 后的翻身→起立→走路，检查进入 Roll 不移动机器人和球，以及观测维度、公共字段与独立归一化。

合并仿真地址和转发端口仍为 **8095**，原有球摩擦、网页摇杆及 Joints 力矩显示保留。

## 推力测试

展开 **推力测试**，选择机器人朝向下的前/后/左/右方向，设置 **推力 (N)** 和 **持续时间 (s)**，点击 **Push（施加推力）**。

- 默认向后 60 N、0.2 秒，力度可调 0–300 N、时间可调 0.02–1 秒。
- 外力作用于当前选中机器人的 `torso_link`，方向在按下时转为世界坐标并锁定，持续时间按仿真步计算。暂停时剩余时间不会消耗。
- 到时自动清零；**取消推力**或 **Reset Environment** 可清除推力。连续点击会重新开始一次推力，不会把力叠加。
- 推力不切换当前模型。倒地后可手动选择 **Roll / LB** 或 **Get Up / RB** 测试恢复；球状态保持不变。

验证：`./scripts/play_walk_kick.sh --push-smoke-test`，检查外力实际进入物理仿真、引起速度变化，以及到期和取消后无残留外力。

### 摔倒保护复选框

网页「摔倒保护」中的「摔倒后取消模型控制（走路 / 踢球）」默认勾选。
仅在 Walk / Kick 模式检测：躯干相对竖直倾角超过 60°，或骨盆离地高度低于
0.30 m，连续达到 0.1 秒后锁定停控。停止策略推理并将机器人执行器增益和偏置
清零，实际驱动力矩为零，仿真继续运行。Roll / Get Up 不受检测影响。

触发后取消勾选不会自动恢复力矩；点击 Walk、Kick、Roll、Get Up 或重置环境
会恢复原执行器参数。可使用推力按钮测试，再选择翻身或起立恢复。
多个并行环境共用模式时，任一环境触发会停止全部机器人的模型控制。

### 推理延迟与电机延迟

网页「控制延迟模拟」提供两个独立复选框，默认均关闭，并可选择「全部模型」
或「仅踢球」。推理延迟范围 0–200 ms、步长 20 ms；电机延迟范围 0–200 ms、
步长 5 ms。页面显示生效范围和两级延迟之和。

控制链路：当前观测 → 模型计算 → 推理结果队列 → 动作缩放为关节位置目标 →
电机目标队列 → 原有 PD 执行器 → 物理仿真。

- 推理延迟：每 20 ms 仍计算一次模型，把输出延后指定控制步再送出；未到期时保持旧指令。
  这是保持 50 Hz 吞吐的固定流水线延迟，并非模拟单个推理线程阻塞或降低推理频率。
- 电机延迟：每个 5 ms 物理步在动作缩放之后延迟关节位置目标，之后才写入电机控制。
  模拟通信/执行的纯滞后，不改变 PD 增益，不添加一阶滤波或机械响应模型。
- 例如 40 ms + 10 ms，t 时刻根据观测生成的结果在 t+50 ms 首次成为电机目标。
  参数若不整除周期则向上取整；网页滑块已按实际周期设置。
- 使用仿真时间，不使用 sleep。暂停时队列不推进，改变播放速度不改变仿真中的延迟。
- 修改设置、手动/自动切换模型、重置场景都会清空两级队列，等待阶段保持当时的关节位置。
  同时开启两个延迟时，等待阶段及队列顺序也包含两级串联的时延。
- 摔倒保护在推理队列之前检查并直接将执行器增益清零，不会被队列延迟。
  停控期间清空队列，翻身/起立接管时按新模式重新建立队列。
- 模型观测中的上一动作仍为送达动作管理器的动作；关节位置和速度来自当前物理状态。
  本功能没有额外给传感器观测添加延迟。
